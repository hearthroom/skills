# Scope

These skills are curated. Changes arrive two ways: an agent feeding back a
lesson from real card work, and pull requests or issues from anyone. Both
meet the same bar, and both are written to [`references/writing-skills.md`](references/writing-skills.md).

## The bar

A change goes in only if it clears both parts:

1. **Observed failure.** Something went wrong in real card work: what the
   skill said or left out, what the agent or the card did, and what should
   have happened. "It would be better if" is not enough. A platform fact
   qualifies once it is confirmed in the chat page's source or the CLI manual.
2. **Fits the toolkit.** It follows the writing guide and does not bring back
   anything in [`.out-of-scope/`](.out-of-scope/). A preference that suits one
   author, one card or one model belongs in that card's `README.md` or your
   own agent instructions.

Size does not matter: a one-line fix and a rewrite face the same bar.

## New skills

There are 43 skills, which is already a lot to route between. A new one is
taken only when the work cannot be done by combining the existing skills;
the pull request says which ones were tried and where they fell short. Most
proposals are better as a sentence in the skill that owns the topic.

## Issues

An issue that cannot be judged against the bar gets one round of questions.
With no reply in 14 days it is closed. Rejections close as "not planned" and,
when the idea is likely to come back, get a file here.
